Intent

Evidence

Halt

Stage Addition
Add any extra layer that improves clarity (examples, context, counterpoints, constraints).
Mystery / Invention

Outcome
Produce the actual result: revised text, summary, plan, answer, or new version.
Review / Verification
Test the outcome against the original intent and evidence. Fix obvious errors.
Point Zero with Product

Next Loop
Run the entire cycle again with the updated material.

After 100 full cycles (or when further passes show no meaningful change), close the current loop and open a fresh one at a higher level if needed. This prevents endless spinning while allowing deep iteration when the text is complex.

For difficult or creative text: Run the full cycle multiple times, keeping only changes that add real value.

They exist across numerical computing, optimization, and AI, with roots going back decades in linear algebra.
1. Classic Numerical Version (Linear Systems)
Proposed by James H. Wilkinson, this targets solutions to systems of equations $  Ax = b  $ where floating-point rounding creates small errors.
Basic steps:

Start with an approximate solution $  x  $.
Compute the residual $  r = b - Ax  $ (often in higher precision).
Solve $  A c = r  $ for a correction $  c  $.
Update: $  x \leftarrow x + c  $.
Repeat while the residual stays above a tolerance.

Mixed-precision variant (common today): Factorize $  A  $ in low precision (e.g., single) for speed, then compute residuals and corrections in higher precision (e.g., double). This reuses the expensive factorization and often achieves double-precision accuracy at roughly half the cost of a full high-precision solve.
Pros: Inexpensive per iteration after setup; reliably reduces error when the matrix is reasonably well-conditioned.
Cons: Slow or non-convergent on ill-conditioned matrices (high condition number). It improves accuracy but does not replace a good initial solver.
2. Optimization and Local Search
These treat the problem as finding a high-quality complete solution and then iteratively tweaking it.
Examples include hill-climbing, heuristic repair for constraint satisfaction problems, and many gradient-based methods. Each step evaluates a local change and accepts it only if it improves an objective function or reduces conflicts.
Pros: Simple to implement; works when solutions are states rather than paths.
Cons: Can get stuck in local optima; performance depends heavily on the starting point and neighborhood definition.
3. AI / LLM Self-Refinement (Most Relevant to Text Processing)
Modern examples use large language models to critique and revise their own outputs at inference time. The best-known is Self-Refine (Madaan et al., 2023).
Core loop:

Generate initial output from the input.
Generate feedback/critique on the output (specific aspects: correctness, style, constraints, missing elements).
Refine the output by incorporating the feedback.
Repeat (typically capped at 3–4 iterations; early stop if feedback indicates the output is sufficient).

The same model handles generation, feedback, and refinement via carefully designed prompts. No extra training is required.
Reported results (on GPT-3.5 / GPT-4): Average ~20% absolute improvement across tasks including code optimization, readability, constrained generation, and dialogue. Gains are smaller on pure math reasoning. Improvements usually plateau after 2–3 rounds.

General Traits Across All Types

Feedback mechanism is central: residual error, objective value, or self-critique.
Stopping rules matter: fixed iteration budget (e.g., your 100-loop example), convergence threshold, or self-detected “good enough.”
Trade-offs: More iterations usually improve quality up to a point, but increase compute/time and risk of oscillation or overfitting to flawed feedback.
When it helps most: Problems with clear, measurable error signals (numerics, code with tests, constrained text). Less effective on highly ambiguous or creative tasks where “better” is subjective.

Add a short decision step:
"Stability Check" — Compare the Product from this loop against the Product from the previous 2–3 loops.

If change is below a clear threshold (e.g., no new meaningful content, contradictions resolved, or length/stability plateau), exit early and move to final output.
Otherwise continue.

This prevents wasting cycles once returns diminish, which is common after 8–15 iterations in most text tasks.
2. External Evidence Injection (inside Validation Loop)
At the Evidence → Halt stage, add an optional branch:
"External Pull" — If the text contains claims, numbers, or references that need verification, pause and bring in outside sources (search, documents, calculations, or domain knowledge).
Then feed the verified material back into the same Validation Loop before deciding Halt or proceed.
This makes the loop stronger for factual or technical text where pure internal review is insufficient.
3. Degradation / Failure Branch (new side loop after Halt)
If Halt decides the current Product is worse than the previous one (rare but possible), trigger:
"Rollback + Note" — Revert to the last stable Product, log the reason for the bad step, and either skip to the next loop or reduce intensity for the following pass.
This adds basic error recovery that standard iterative loops often lack.
4. Meta-Synthesis Layer (after the 100-iteration cap or final Return Loop)
Once the main RGL finishes:
"Stack Review" — Run one final high-level pass over the entire chain of 100 Products.
Summarize: What core changes accumulated? What assumptions were overturned? What new structure emerged that wasn’t in the original text?
Output this as a short meta-report alongside the final Product.
Useful when the goal is not just a refined text but also insight into how the text evolved.
5. Resource / Cost Gate (optional at start of each Return Loop)
Simple check:
"Effort Assessment" — Ask: “Does the expected gain from the next loop justify the time/compute?”
