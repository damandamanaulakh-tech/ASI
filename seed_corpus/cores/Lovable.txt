sourceborn ARD-RGL 1.0 — Full Build PlanThis is the complete blueprint. Read it once, push back on anything that feels wrong, then approve to flip me into build mode.---### 1. What we are actually buildingA **universal reasoning router**. The user pastes raw text (a question, a claim, a mess of thoughts, a project brief, a contradiction they're stuck on). The engine runs the full ARD-RGL pipeline over it: it preserves the raw source, separates fact from feeling from assumption from claim, classifies every claim by domain, hunts for sources, scores resonance, builds an evidence ledger, generates wild branches, attacks the strongest conclusion with a falsifier, places every claim on a proof ladder, audits per domain, tags external grounding honestly, produces a structured Final Output Template, and renders a 25-field Scoreboard. The human then chooses to Continue (feeds output as the next Point Zero), Stop, Collapse a branch, Reverse, Re-anchor to raw source, Inject Synthetic Fuel, Run the Doubt Engine again, Run External Grounding, Save, or Propose Engine Mutation.The LLM is the worker. The engine is the brain. The engine logic — stages, prompts, scoring, persistence, override ledger — lives in our code, not in the model.---### 2. Stack (and why each choice)- **TanStack Start v1** — already scaffolded. Server functions for the engine, file-based routes for the UI. SSR-safe.- **Lovable AI Gateway** as the model provider. Default worker model: `anthropic/claude-sonnet-4-5`. Swappable per loop via a model picker to `openai/gpt-5`, `google/gemini-2.5-pro`, `google/gemini-3-flash-preview` (for cheap fast loops). This satisfies your **Stage 39 Model Independence Layer** — no provider lock-in, the prompts and scoring live outside the model.- **Lovable Cloud (Postgres + Auth + Storage)** for persistence instead of MongoDB. No hand-rolled JSON parsing.- **Tailwind v4 + shadcn** (already installed) for the UI. One schema file, imported by both the prompt builder and the persistence layer.---### 3. The whole pipeline, executed as 9 grouped passesRunning 50 separate model calls per loop would cost a fortune and take minutes. Instead I group stages that share context into single structured-output calls. Each pass is one `generateText` with `Output.object` returning a strict schema covering exactly the stages it owns. Each pass streams its result to the UI the moment it lands, and persists immediately. The user sees the loop being built stage by stage in real time.**Pass 1 — Governance + Pre-Loop Self-Check** (Stages 00, 01)Reads only the raw input. Returns: detected bias pressure, urgency, stakes dial, time horizon, depth requirement, hidden goal, success criteria, expected deliverable type (answer / plan / code / prompt / theory / proof / test / document), MODE, DEPTH, RISK LOAD. This pass also extracts the Point Zero record: raw_text, timestamp, session_id, visible intent, inferred hidden goal, active project.**Pass 2 — Raw Capture + Noise Strip + Canon Extract** (Stages 02, 03, 04, 05, 07)Preserves the raw source verbatim (never touched again). Splits everything into FACT / FEELING / ASSUMPTION / PRESSURE / CLAIM / MYSTERY / INVENTION_SEED / COMMAND / RISK_SIGNAL / UNKNOWN. Pulls canonical/symbolic resonance from holy texts, archetypes, proverbs, prior memory — but tags every one of them as **pattern support, not factual proof**. This guardrail is in the prompt and re-validated by code: if a canon item ever shows up later attached to a [PROVEN] tag, the engine throws.**Pass 3 — Source Hunter + Domain Classifier + Resonance + Claims + Evidence Ledger** (Stages 06, 08, 09, 10, 11)Hunts for living anchors (user file references, prior memory, similar past outputs, real examples). Classifies every claim by domain (personal / scientific / mathematical / historical / legal / financial / medical / technical / spiritual / symbolic / operational / product / speculative / synthetic / unknown). Scores resonance 0/25/50/75/100. Atomizes the input into claims: `claim_id`, `claim_text`, `source_link`, `claim_type`, `domain`, `evidence_status`, `proof_level`, `proof_debt`, `contradiction_count`, `falsifier_status`. Tags each claim with [FACT] / [INFERENCE] / [GUESS] / [SYNTHETIC] / [UNKNOWN] / [REFERENCED] / [CONDITIONAL] / [OPEN] / [CONTRADICTED] / [TESTABLE] / [UNTESTED]. [PROVEN] is **forbidden at this pass** — it can only be set later by the Domain-Adaptive Auditor.**Pass 4 — Dual Analysis + Human Layer + Archetype Swarm + Parallel Hypothesis** (Stages 05-Core-Gate, 12, 13, 13.1)Runs Track A (wild/sourceborn: symbolic, hidden pattern, inversion, recursion, mystery, invention, archetype, power) and Track B (reality-grounded: known, testable, supported, contradicted, missing, actionable) — kept rigorously separate in the output schema, never blended. Extracts the Human Layer: mask, payoff, wound, threat, loyalty, drive, desire, fear, identity, control need, status pressure, hidden personal stake. Runs the Archetype Lens Swarm (Child, Enemy, Outsider, Future Self, Affected Person, Scientist, Builder, Investor, Judge, Operator, Skeptic, Historian, Spiritual, Market, Failure) — toggle-gated. If Parallel Hypothesis is toggled on, spawns 8–20 simultaneous hypotheses, each with hypothesis_id, core idea, supporting pattern, opposing evidence, synthetic load, proof debt, reality anchor, expected test, collapse score. The hypotheses are **ranked**, not presented as equals.**Pass 5 — Fractal Branch + Collapse Scorer + Pattern Scan + Contradiction + Falsifier** (Stages 14, 15, 16, 17, 18, 19, 20)Command/Risk gate runs first: any branch that is illegal/harmful/high-cost/irreversible is tagged with risk_type, practical danger, what's unknown, what can be safely analyzed, what cannot be responsibly executed. Generates branches by type (Direct, Inversion, Opposite-World, Extreme Case, Historical, Scientific, Mythic, Product, Business, Mathematical, Human Behavior, Failure, Synthetic). Scores each branch on relevance, novelty, evidence strength, reality anchor, synthetic load, proof debt, force-fit risk, human usefulness, actionability, risk, reversibility, breakthrough potential. Collapses into: strongest, most dangerous, most useful, most speculative, requires-human-review. Then runs the Contradiction Engine (within raw input, between claims, feeling vs fact, evidence vs conclusion, symbolic vs proof, desired vs available, short-term vs long-term) and the Doubt Engine / Falsifier (attacks the strongest conclusion: what if wrong, what if opposite, what would a critic say, what data destroys this, what assumption is weakest, what is force-fitted, what is emotionally attractive but logically weak).**Pass 6 — Proof Ladder + External Grounding + Domain-Adaptive Auditor + Experiment Designer + In-Silico Validation** (Stages 21, 21.5, 22, 23, 23.1)This is the rigor pass. Detailed below in Section 5. Every claim ends with a proof_level (RAW / NOTICED / POSSIBLE / PLAUSIBLE / REFERENCED / SUPPORTED / TESTED / PROVEN), an external_grounding tag, a domain-audit verdict, a designed experiment, and an in-silico validation status. [PROVEN] is only emitted when the auditor passes for that domain — synthetic cannot pass Level 3 without evidence, canonical resonance cannot prove a factual claim, human command cannot make something true.**Pass 7 — Resolution Gateway + Output Generator + Vibe Schema + Product Checkpoint** (Stages 24, 25, 26, 27)Classifies result: SOLVED / PARTIAL / OPEN / WRONG_QUESTION / NEEDS_DATA / NEEDS_HUMAN_DECISION / NEEDS_TEST / HIGH_RISK / SYNTHETIC_ONLY / CONTRADICTED. Generates the Final Output (direct answer, plan, prompt, code, theory map, or next action — whichever fits the deliverable type from Pass 1). Tags vibration/energy (calm / urgent / angry / wounded / pressured / obsessive / breakthrough / defensive / exploratory / high-risk / identity-loaded / mystery-loaded). Checks Product Checkpoint: can this become an app feature, prompt, engine rule, document, research task, experiment, business workflow, theory module, archive item, human decision, action plan.**Pass 8 — Logic Wall + Stuck Protocol + Self-Healing + Synthetic Fuel + Hyper-Synth + Mutation Proposal + Proof Debt + Re-Anchor** (Stages 28–35)Detects stalls (data / logic / frame / complexity / motive / moral / pattern / stakes / time / evidence / proof). For each stall: name it, cause, what's missing, how to unstick. Runs the Stuck Protocol if needed (return to Point Zero, drop one assumption, attack strongest conclusion, inject synthetic fuel with proof debt). Logs self-healing observations (engine flaw, cause, correction, repeated failure, overreach, hallucination risk, weak source use, missed human layer, excessive complexity, under-analysis). If Synthetic Fuel was used, each item gets synthetic_id, reason, expected value, proof debt, expiry point, review requirement. Hyper-Synth (toggle-gated) tags items with high_synthetic_load, high_proof_debt, possible_distortion, reality_anchor_required, force_fit_risk. Engine may propose a self-mutation — logged with proposed change, why needed, expected outcome change, risk, distortion of original ideology, human approval status (defaults to pending). Reality Re-Anchor: does this still match the raw source? Yes/no/partial with diff.**Pass 9 — Full Compilation + Breakthrough Lock + Scoreboard + Feed Forward** (Stages 36, 49, 49.5, plus the Scoreboard from the Final Output Template)Compiles every prior pass into the Final Output Template. Runs Breakthrough Lock scoring (novelty, feasibility, paradigm impact, testability, usefulness, evidence gap, force-fit risk, time to validate, product potential, theory value) and classifies as ordinary / useful / strong / breakthrough_candidate / high_risk_synthetic_breakthrough / not_ready. Emits the full 25-field Scoreboard. Stores feed_forward: accepted_result, unresolved_gaps, next_loop_seed, updated_proof_debt, updated_scoreboard.After Pass 9, the **Human Review Gate** renders. Nothing auto-advances. The loop is frozen until the human acts.---### 4. Cross-cutting stages (run as middleware, not as their own pass)Some stages are not their own pass — they wrap or follow the pipeline as code, not prompts:- **Stage 37 Source Protection Firewall** — server-side. Internal scoring, scoring rationale, raw branch deliberations, and engine-mutation proposals are never sent to the client unless the human explicitly requests "expose internal state." The publishable client only sees what the Final Output Template prescribes.- **Stage 38 Human Override Ledger** — every Human Review button click writes a row: timestamp, user_id, loop_id, action (continue / stop / collapse / reverse / inject / accept / reject / re-anchor / force_branch / rename / freeze / mutate). The ledger explicitly does **not** elevate any claim to PROVEN — overrides control direction, not truth.- **Stage 39 Model Independence Layer** — model picker at the top of each run, stored on the loop record. Worker is swappable mid-project.- **Stage 40 Hierarchy Shift** — exposed as a manual button in the Stuck UI. The user can ask the engine to re-run the current loop at a different level (word / claim / source / pattern / human / system / domain / proof / product / cosmic-symbolic).- **Stage 41 Data Mining** — every new loop's Pass 3 also receives a compact summary of prior loops in the same project (raw source history, prior evidence ledger highlights, contradictions, proof debt, repeated patterns, failed branches, accepted outputs). Implemented as a server-side query that builds a "memory packet" before the call.- **Stage 42 Compute Route** — for each unresolved claim the auditor picks one of: LLM_reasoning / code_execution / database_lookup / external_API / manual_source / simulation / file_analysis / human_input / no_compute_possible. v1 routes everything to LLM_reasoning or manual_source honestly; later versions wire real code execution and external APIs without changing the schema.- **Stage 43 Persistence** — schema in Section 6.- **Stage 43.5 Cross-Domain Fusion** — toggle-gated. When on, Pass 4 receives an extra instruction to scan domain pairs (science×history, biology×business, math×psychology, etc.) and report fusion insights with domain_A, domain_B, fusion_insight, evidence_strength, force_fit_risk, proof_debt, test_path.- **Stage 44 Thread Lock** — server-side. Once a loop starts, its Point Zero and raw source are frozen. Subsequent passes cannot mutate them. Any attempted overwrite throws. Prevents context drift, branch mixing, silent mutation.- **Stage 45 Sync-State** — after each pass, a single sync write to the loop record. The UI polls/streams that record.- **Stage 46 Raw Hex Dump** — exposed as a "Deep Linguistic Scan" button on the raw source card. On demand only (expensive). Returns exact wording analysis, repeated words, emotional spikes, contradiction words, command words, hidden assumptions, symbolic markers, pressure markers.- **Stage 47 Kernel Dive** — exposed as a "Kernel Dive" button on the Final Output. Returns root claim, root fear, root missing proof, root contradiction, root invention, root decision.- **Stage 48 Architect Link** — small panel in the output: does this become a rule / module / data / UI / prompt logic / scoring / experiment? Human can tick one and it gets logged.- **Stage 50 Eternal Loop** — Continue button takes the Final Output and seeds it as the next loop's raw input. The new loop links to its parent via parent_loop_id, building a tree.- **Stage 50.5 Meta-Core Upgrade** — engine mutations from Pass 8 land in a queue. The user reviews them in a dedicated `/mutations` page. Approving one writes a new version of the prompt/schema file. No silent core change.---### 5. Deep dive: Stage 21.5 External Grounding (you asked about this one specifically)This is the stage where the engine has to be most honest.
