## 3 · PASS 0 — DECLARE THE END FIRST

**This is the first act, before any search for a beginning.**

```text
0. DECLARED END / OBSERVED EVENT / RESULT
              ↓
      WHAT EXACTLY ENDED, CHANGED OR FORMED?
```

**The end defines which earlier reality matters.** Without it, reverse
engineering expands forever. Sequence depth is therefore *whatever depth is
required to explain the declared end at the chosen resolution* — 10 stages, 30,
300, 3,000,000. **The grammar is universal; the number is not.**

Then the triple pass:

| Pass | Direction | The question |
|---|---|---|
| **1** | **END → START** | Did we find everything that had to exist? |
| **2** | **START → END** | If those things existed, can they *legally* produce the declared end? |
| **3** | **END → START** | Attack it. Is anything unexplained, borrowed without origin, unclosed, unconnected? |

An **UNCONNECTED DOT** is any of: a result with no producer · a transition with
no activation rule · a threshold with no evaluator · a dependency with no
provenance · an exception with no controlling contract · a required
sub-sequence not terminal · an unexplained identity change · a memory that
traces to no sequence.

On a failure: **do not alter history.** Open an investigation sub-sequence,
close it, return it, run the triple pass again.

## 4 · THE SIX CORE OBJECTS — validated by both walks, locked

### 4.1 THRESHOLD — separated from trigger, carried on edges

**TRIGGER** = something changed / was observed / occurred.
**THRESHOLD** = the condition that must become true before the transition is
*permitted* to fire. A condition can exist for years without causing a
transition. Threshold answers **"why now?"**

```text
EDGE { source · target · activation_event · threshold_condition
       evaluator · evaluation_time · recheck_condition · status }
```

Nine types: **VALUE · RANGE · TIME · EVENT · COUNT/QUORUM · CONFIDENCE/PROOF ·
STATE · ABSENCE · COMPOSITE** (A AND B · A OR B · A UNLESS C).

The recheck contract — never a vague "later":

```text
RECHECK WHEN: sub-sequence returns OR resource-state changes
              OR deadline reached OR external event received
```

Thresholds live **on edges, never as another numbered stage.**

### 4.2 SEQUENCE CLOSURE ≠ ENTITY OUTCOME

| Sequence | Entity |
|---|---|
| destruction: CLOSED SUCCESS | TERMINATED |
| repair: CLOSED FAILURE | persists, DEGRADED |
| pyramid build: CLOSED SUCCESS | INSTANTIATED / persisting |
| gravity: CLOSED | NOT APPLICABLE |

**ENTITY OUTCOME:** persists · modified · degraded · repaired · transformed
(identity decision required) · split · merged · consumed · terminated · new
entity instantiated · absent · unknown · not applicable.

**CLOSURE is a sequence word only.** Entities **persist, cohere, degrade,
terminate**. The physical phenomenon may continue while the analytical sequence
about it closes — no contradiction once the words are separated.

### 4.3 SUB-SEQUENCE CONTRACT

```text
SUB_SEQUENCE_CONTRACT {
    sequence_id · attached_to · attached_at_node
    reason
    requested_result · return_schema
    scope · context_snapshot
    controller
    activation_condition
    close_condition          ← the sub-sequence's own finish line
    acceptance_condition     ← the requirement of the one that opened it
    required_or_optional
    evidence_requirement · proof_depth
    dependencies · deadline · termination_policy
}
```

**close_condition ≠ acceptance_condition.** Search for water: closes
legitimately as CLOSED FAILURE ("search completed, none found") while the
requirement stays unresolved and the next sub-sequence opens.

### 4.4 OPEN-SEQUENCE LEDGER

> **"Without the ledger, closure is philosophy. With the ledger, closure becomes
> machine-executable."**

```text
required_open(node) == 0  AND  all_required_returns_accepted == TRUE
→ only then may that node close
```

### 4.5 DRIVER ORIGIN — Want beside Need, never in the spine

**NATURAL DYNAMICS · NEED · WANT · EXTERNAL DEMAND · GOAL · OPPORTUNITY ·
CURIOSITY · DAMAGE/DEVIATION · RELATIONAL · PROMISE ACTIVATION.**

Hunger → NEED. Spicy food → WANT, which opens a *new* sequence and never joins
the eating one. Pyramid → GOAL + EXTERNAL DEMAND. Research → CURIOSITY.
Gravity → NATURAL DYNAMICS, **no fake requirement invented.**

### 4.6 CONTROLLER — mandatory

**NONE/NATURAL · SELF · DISTRIBUTED SELF · EXTERNAL · JOINT · META · UNKNOWN.**

**DRIVER ≠ CONTROLLER.** A person may feel the driver while another controls the
available action. Self-repair needs `SELF`; homeostasis is **repeated
threshold-bounded closed episodes**, never one immortal loop.

## 5 · THE PRIMITIVES THE MAHABHARATA FORCED — locked

The test produced 23 named things. Compressed honestly, these are the ones that
do not collapse into the six:

1. **SEED BEFORE CARRIER.** The necessary condition can exist before any carrier
   is born. Karna was seeded before Karna. A person may be **carrier, executor,
   obstacle, trigger, bridge, witness, controller or closure-point** of a
   sequence that started earlier — not its originator.
   *Precision:* where no intentional actor exists yet, the object is a **seed /
   latent dependency / stored commitment** — not "intent". Intent needs a carrier.
2. **ACTOR VIEW / KNOWLEDGE DISTRIBUTION.** Reality ≠ what each actor knows. A
   decision is generated from the actor's *available* reality, not the full one.
   Without this the engine mis-models deception, teaching, negotiation, hidden
   identity, discovery.
3. **PRIORITY / ARBITRATION.** Love, shame, status, fear, duty can all hold at
   once; one dominates the output. Outcomes are five, not two: **followed ·
   broken · overridden · in conflict · not applicable.**
4. **EXCEPTION CONTRACT.** A lower rule breaks only under a higher controlling
   objective, with normal rule, why it exists, blocked objective, alternatives,
   trigger, scope, permitted action, cost and closure recorded. **The exception
   closes; the rule survives.** Without this the engine compresses one bounded
   case into "break rules for better outcomes" — which is precisely what is
   *not* meant.
5. **LATENT RESULT / LATENT TRIGGER.** A result exists, stays inactive, persists
   as state/memory/relation, and becomes active input to a **new** sequence when
   a later threshold fires. The old sequence never reopens.
6. **DOWNSTREAM-CRITICAL STATE CHANGE.** A locally tiny event can carry critical
   global weight. Every event records **local effect · future effect · global
   role**, or the engine discards the decisive thing as noise.
7. **CONVERGENCE WINDOW.** Many independent old sequences arrive at one
   execution window. **The 18 days are a synchronization point, not an origin.**
8. **CLOSURE SCOPE.** "Closed" must declare *what*: action · promise · character
   · event/war · institution · era. One closure never implies the larger ones.
9. **OBSERVER / WRITER SEQUENCE.** The event closes; a *separate* sequence
   records it. **What happened ≠ what was preserved ≠ what a later reader
   interprets.**
10. **RULE INERTIA.** An internalised rule keeps driving action after the
    environment that made it fair is gone — an explanation class to test, never
    to assert.
11. **PROMISE / FUTURE-ACTION COMMITMENT.** `{created_at_event · target ·
    intended_result · activation_condition · persistence · owner ·
    closure_condition}`. The *promise-creation* sequence closes; its result is a
    stored future trigger; the *fulfilment* sequence is new. **That is how vows
    span decades without any sequence staying open for decades.**
12. **REPRESENTED FUTURE SEQUENCE**, distinct from desired future state. One is
    *what end do I want*; the other is *where does my action sit in a path
    larger than I can see*. Arjun before the war is the second.
13. **RESULT MULTIPLICATION.** One closed sequence fans out into resource,
    memory, entity, environment, problem, rule, capability, opportunity,
    discovery. **This is the structural answer to "everything closed, but a
    million inventions."**

**And one rule the owner's own example wrote:** Kunti's mantra was a low-stake
curiosity test, closed and abandoned — and its discarded packet became the
load-bearing counterweight of the whole war. Therefore: **a closed packet is
never discarded.** A low-stake abandoned result can become a high-stake
dependency later.

## 6 · THE INVARIANTS

1. **THE BARRIER LAW** — replacing "no sequence can move while open", which
   would wrongly freeze parallel branches:

   > **No dependent edge may cross a closure barrier while a required
   > predecessor or sub-sequence contract remains open.**

   The one that opened it may sit OPEN/**SUSPENDED** at that barrier while its
   independent branches keep moving.

2. **NO IN-PLACE LOOP.** Unresolved → suspend at barrier → open a new sequence →
   it closes → returns → re-evaluate. `TEST S₁ fail → REPAIR S₂ → RETEST S₃
   success → main continues.` Three sequences created, each finished, each
   closed, each returned something.

3. **NO REOPEN.** `S₀ CLOSED` + new evidence → `CREATE S₁`, `S₁.references =
   S₀`. The word *reopen* is removed from the grammar. History is never
   rewritten.

4. **CLOSURE is reserved for sequence execution.** Entities persist / cohere /
   degrade / terminate.

5. **ENCOUNTER IS CONDITIONAL.** Relation exists? → yes: COUPLING · no:
   ENCOUNTER/ACCESS → COUPLING.

6. **NEVER MANUFACTURE A SOURCE.** A dependency with no origin is recorded as
   **UNKNOWN SOURCE** and carried as an unconnected dot. Every edge carries
   epistemic status: **KNOWN · SUPPORTED · INFERRED · SPECULATIVE · UNKNOWN ·
   CONTRADICTORY.**
