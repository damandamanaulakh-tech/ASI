## The definition

> **A sequence is the ordered evolution of something from one distinguishable
> condition into another, where each position exists because of what came
> before, what is available now, what rules or forces act on it, and what future
> states remain possible.**

`A → B → C → D` is **one visible form** of sequence, not the definition of it.

Three levels of the same definition:

| Level | Definition |
|---|---|
| **Most vague** | Sequence = ordered change. |
| **System** | Sequence = an ordered relationship between states in which transitions are governed by dependencies, conditions, available resources, forces, rules, memory, and possible outcomes. |
| **Sourceborn ASI** | Sequence = the dynamically constructed path connecting a present reality to a target reality — or reconstructing a present reality from its causes — by discovering required states, dependencies, conditions, transitions, alternatives, failures, feedback, and available material rather than assuming a fixed linear chain. |

And below all three, the absolute primitive:

> **Sequence exists whenever at least two distinguishable configurations have a
> meaningful relation of order, dependency, transformation, or derivation.**

> `Sequence = Differences connected by meaningful order.`
>
> `Living Sequence = Differences + Order + Conditions + Transition + Memory + Possibility.`

## The unit is the transition, not the step

> **A step is only a snapshot.**

The primitive unit:

```text
Source State + Context + Trigger/Force + Rule → Transition → Resulting State
```

The result then becomes the source of the next transition:

```text
S₀
↓
[Context₀ + Trigger₀ + Rule₀]
↓
S₁
↓
[Context₁ + Trigger₁ + Rule₁]
↓
S₂
...
```

`Seed → Tree` looks like a sequence but hides almost everything. The actual
sequence contains:

```text
Seed → condition exists → water available → temperature acceptable
→ biochemical activation → germination → root formation
→ resource acquisition → growth → branching → damage → repair
→ adaptation → reproduction → decay
```

And things can happen **simultaneously, fail, reverse, branch, repeat, or never
happen.**

> **Therefore: sequence is not necessarily linear order. Sequence is structured
> dependency across changing states.**

The fuller shape, still a flattened representation:

```text
                         ┌──── Alternative ────┐
                         │                     ↓
Past → State → Condition → Decision → Transition → State
          ↑                  │                    │
          │                  └──── Alternative ──┤
          │                                       │
          └──────── Memory / Feedback / Repair ───┘
```

---

## Sequence does not inherently mean time

`1 → 2 → 3` may be temporal order. But:

```text
Foundation → Column → Beam → Roof
```

is **dependency order** — the roof may be designed before the foundation is
constructed. And:

```text
Question → Evidence → Inference → Conclusion
```

is **epistemic/logical order**. And:

```text
Outcome ← Requirement ← Prerequisite
```

is **reverse dependency order**.

---

## Two meanings of sequence

| | Asks | Shape |
|---|---|---|
| **Observed sequence** | What happened? | `A → B → C → D` |
| **Generative sequence** | What had to be true for D to become possible? | `Requirements → Conditions → Interactions → Intermediate states → D` |

**Phase 1 — "reverse, and available material" — points to the second.**

A conventional system asks `A → ?` and predicts the next step. This system asks
instead:

```text
Target = D

D required what?  ↓ C
C required what?  ↓ B
B required what?  ↓ A
```

Then compares the reconstructed chain against what actually exists:

```text
Desired Reality          Available Reality
D                        A?
↑                        B?
C                        resources?
↑                        knowledge?
B                        conditions?
↑                        constraints?
A
```

And the executable sequence is generated from the intersection:

```text
Required Chain
      ∩
Available Material
      ∩
Current Reality
      ∩
Constraints
      ↓
Executable Sequence
```

## The 25 dimensions

Every one is a dimension of sequence in its own right, not a stage.

| # | Dimension | What it is |
|---|---|---|
| 1 | **Position** | where something currently is |
| 2 | **Predecessor** | what produced this position |
| 3 | **State** | what exists at that position |
| 4 | **Context** | surrounding conditions |
| 5 | **Availability** | what resources / information / options are currently accessible |
| 6 | **Trigger** | what causes movement |
| 7 | **Rule** | what constrains how movement can occur |
| 8 | **Transition** | the actual change |
| 9 | **Result** | the state produced |
| 10 | **Dependency** | what must already exist |
| 11 | **Direction** | forward, backward, sideways, recursive |
| 12 | **Branch** | multiple possible next states |
| 13 | **Loop** | return to an earlier state |
| 14 | **Memory** | effects from previous states carried forward |
| 15 | **Feedback** | later outcomes modifying earlier assumptions / rules |
| 16 | **Interruption** | sequence stops because an external/internal condition changes |
| 17 | **Repair** | damaged / invalid sequence is restored |
| 18 | **Reversal** | system moves toward an earlier condition |
| 19 | **Compression** | many transitions represented as one apparent step |
| 20 | **Expansion** | one apparent step decomposed into its hidden transitions |
| 21 | **Parallelism** | multiple sequences occur simultaneously |
| 22 | **Synchronization** | independent sequences must meet before continuation |
| 23 | **Selection** | one possible path is chosen from several |
| 24 | **Termination** | no next transition is required / possible |
| 25 | **Re-entry** | something previously terminated can enter a new sequence |

## The kinds

Not separate ideas — manifestations of the same primitive,
`Stateₙ —[relation/transition]→ Stateₙ₊₁`.

```text
SEQUENCE
│
├── Temporal        Before → During → After
├── Causal          Cause → Effect
├── Dependency      Requirement → Dependent
├── Logical         Premise → Inference → Conclusion
├── Construction    Components → Assembly → Whole
├── Discovery       Unknown → Observation → Understanding
├── Decision        Condition → Alternatives → Selection
├── Execution       Intent → Action → Result
├── Biological      Stimulus → Perception → Interpretation → Emotion → Action
├── Learning        Exposure → Processing → Pattern → Memory → Retrieval
├── Failure         Stress → Fracture → Degradation → Failure
├── Repair          Detection → Diagnosis → Intervention → Recovery
├── Reverse         Outcome → Causes / Requirements
└── Recursive       Output → New Input → New Output → ...
```

Sequence exists in matter, thought, emotion, language, mathematics, causality,
memory, biological development, organizations, markets, software, religion,
narratives, decisions, AI reasoning, and human life.

## The record

**Not** `SEQUENCE = ordered list`. Closer to:

```text
SEQUENCE
=
{
    Origin,
    Current_State,
    Relation,
    Transition,
    Conditions,
    Dependencies,
    Available_Material,
    Constraints,
    Direction,
    Alternatives,
    Memory,
    Feedback,
    Result,
    Target
}
```

**None of those is mandatory except that there must be:**

```text
Difference
+
Relationship
+
Order
```

Without difference there are not multiple distinguishable positions. Without
relationship they are merely unrelated things. Without order or dependency there
is no sequence.

## Static and living

A **static** sequence is a fixed `A → B → C` chain. A **living** sequence is
conditional, contextual, recursive, remembered, interpreted, repaired, and
continuously regenerated.

> **Human → AI → Holy Books → ASI do not contain fixed chains.** Their sequences
> are living ones. This distinction is expected to matter when Phase 2 reaches
> them.

---

## Binding rules

1. **Never present a step as the unit.** A step is a snapshot. The unit is the
   transition — source state, context, trigger, rule, result.
2. **Do not assume linear order.** Check for branch, loop, parallelism, reversal,
   interruption and termination before laying anything out as a chain.
3. **Say which order is meant** — temporal, causal, dependency, logical,
   construction, discovery, decision, execution, biological, learning, failure,
   repair, reverse, or recursive. Sequence does not default to time.
4. **When a target is named, build generatively, not predictively.** Reconstruct
   what the target required, then intersect the required chain with available
   material, current reality and constraints. The intersection is the executable
   sequence — not the required chain on its own.
5. **A compressed step must be expandable.** If a step cannot be decomposed into
   its hidden transitions on request, it is not understood, and saying so is the
   honest answer.
6. **Difference, relationship and order are the only mandatory fields.** Any of
   the other eleven may be absent; none may be invented to fill a gap. An
   invented field is `[SYNTHETIC]`, with proof-debt and expiry.
